# FORMEQUA — 메뉴와 작업 흐름 정리

2026-10-23 사용자의 ‘오른쪽 상단 메뉴와 작업 연결이 어지럽다’는 요청에 따라 실제 목적지·복귀·현재 위치 표시를 점검하고 수정했다. 2026-10-24 단일 스크롤과 홈 복귀 요구를 반영한 현재 내비게이션 버전은 `20261024-onepage1`이다.

## 2026-10-24: 스크롤과 메뉴 클릭을 같은 콘텐츠로 통합

소개만 별도 페이지로 열려 스크롤 흐름과 다른 내용이 보이던 구조를 수정했다. 소개 → 공간 연구 → 모형·대지·사업성은 모두 `index.html`의 연속된 콘텐츠이며, 상단 About·Studies·Atelier는 각각 `#about`·`#projects`·`#studio`로 이동한다. 상세 작업 동작만 기존 대시보드를 연다.

소개 영역에는 A way of seeing, Perspective, 기존 한국어 Approach, Place·Form·Value, Powered by WAN2를 같은 문서 안에 통합했다. 단어별 진입, 방향별 사진 커튼, Studies의 사진·제목 순서, 두 스크롤 장면과 본문 reveal을 유지한다. `about-formequa`는 소개 래퍼에만 적용해 hero 헤더 색상을 덮지 않는다. 원래 About의 중복 헤더·h1·footer는 추가하지 않는다. 소개의 다음 장면은 기존 Studies 제목으로 이어진다.

`about.html`은 별도 소개 내용을 표시하지 않는 호환 진입 주소다. 기본 접속은 홈페이지 `#about`, 기존 `#perspective`·`#method`·`#researcher`·`#approach`는 홈페이지의 같은 앵커로 연결한다. 스크립트 실행이 불가능해도 소개 링크를 직접 누를 수 있다.

문자·사진·본문 모션은 처음부터 동작 줄이기를 사용한 경우와 실행 중 설정을 바꾼 경우 모두 콘텐츠를 읽을 수 있게 한다. 높이 780px 이하에서는 긴 고정 장면을 일반 문서 흐름으로 표시해 하단 문구가 가려지지 않도록 한다. 실제 휠 스크롤·메뉴 클릭·모바일·기존 주소·모션 환경 전환을 포함한 브라우저 검사 31개와 기존 파일럿 표시 검증을 통과했다. 계산·상태·작업실 관련 9개 파일은 변경 전 해시와 일치했다. [검증 기록](navigation-verification-20261024.json)과 작업공간 `.backups/formequa-single-page-20261024/`의 스크립트·화면을 함께 보관한다.

## 2026-10-24: 사진 중심의 Approach·Inquiry 장면

최종 사용자 요청에 따라 제목과 사진을 서로 다른 그리드 행으로 분리했다. 데스크톱에서는 제목 아래에 큰 사진 두 장을 높낮이 차이로 배치하고, 모바일에서는 제목 다음에 사진을 한 장씩 배치한다. 사진 크기는 유지하되 글자·캡션과 겹치지 않게 32~42px의 행 간격을 둔다. 반전 합성을 제거하고 기존의 짙은 올리브 글자색을 사용한다.

`atelier-motion.js`가 두 장면을 함께 관리한다. 일정 면적이 화면에 들어오면 사진 커튼·완만한 확대 해제·문자 진입이 약 2초 동안 자동 완성된다. 휠 이동량에 직접 묶이지 않는다. 장면 전체가 화면 밖으로 벗어나면 다시 준비하고, 역방향 재진입에도 재생한다. 동작 줄이기 환경에서는 사진과 문자를 즉시 표시한다. 모든 화면에서 일반 문서 흐름을 사용하며, 진입 이동도 수직 18px로 제한해 모션 도중에 글자가 사진 영역을 침범하지 않게 한다. 캐시 버전은 `20261024-photoseparate1`이며, 기존 히어로·본문·Studies 진입 모션은 유지한다. `about-formequa.js`는 기존 About 주소 연결만 맡는다.

## 2026-10-24: 브랜드 클릭과 홈 복귀 통일

어느 화면에서든 FORMEQUA 브랜드와 작업실의 ‘아뜰리에로’ 복귀 링크를 누르면 홈페이지 `#home`, 스크롤 0으로 이동한다. 기존 URL의 `returnTo=#studio`·`#feasibility`는 홈 복귀 위치를 덮어쓰지 않는다. 홈페이지 헤더·소개 구간·하단 브랜드, About 헤더·하단, 작업실 로고·복귀 링크, 모형 편집 패널 브랜드·상단 복귀 링크에 적용했다. 홈 이동은 즉시 실행하고, `pageshow`에서도 `#home` 위치를 보정한다. 다른 섹션 메뉴와 ‘About FORMEQUA’ 소개 링크의 목적지는 유지한다.

기존 작업 상태 저장은 유지한다. 아래 2026-10-23 기록 중 ‘원래 구간/사업성 요약으로 복귀’는 이 요구로 대체되었다. 격리된 Edge에서 데스크톱·모바일·일반/줄인 모션·반복 클릭·쿼리 URL·브라우저 뒤로 가기·설계값 보존을 재검증했다. 결과와 스크립트는 작업공간 `.backups/formequa-home-top-20261024/`에 보관한다.

## 확인한 혼란과 수정

| 기존 상태 | 수정 |
|---|---|
| 홈페이지와 About의 마지막 메뉴가 서로 다름 | 두 페이지에서 동일한 메뉴 이름·순서·의미를 사용 |
| Perspective는 사업성 요약인데 About의 perspective는 연구 관점 | 전역 메뉴를 About·Studies·Atelier로 통일하고 사업성은 Atelier 내부 항목으로 연결 |
| 상세 보기의 목적지가 모형인지 분석인지 구분하기 어려움 | ‘모형 크게 보기’와 ‘사업성 상세 검토’의 이름·진입 화면을 구분 |
| 사업성 상세 검토가 모형 집중부터 열려 분석표가 보이지 않음 | `view=workspace&tab=tab-finance`로 직접 열고 복귀는 `#feasibility` |
| 스크롤을 빠르게 옮기면 이전 메뉴가 선택된 채 남을 수 있음 | 현재 보이는 구간으로 메뉴를 결정하는 공통 로직 적용 |
| 페이지를 건너뛴 앵커 진입에 스크롤 여백이 이중 적용 | section의 중복 scroll-margin 제거, 고정 헤더 높이와 초기 fragment 이동 시점 보정 |
| 모형 집중에서 아뜰리에로 가려면 전체 작업실을 먼저 열어야 함 | 모형 도구막대에 아뜰리에 직접 복귀 추가 |
| 모바일 메뉴가 펼쳐지는 순간 첫 링크에 초점이 가지 않음 | 표시가 반영된 두 프레임 뒤 초점 이동, Tab 순환·Escape 복귀 적용 |

## 최종 전역 메뉴

| 메뉴 | 보조 설명 | 목적지 |
|---|---|---|
| About | 포메퀴아 소개 | 홈페이지 `#about` |
| Studies | 공간 연구 | 홈페이지 `#projects` |
| Atelier | 모형·대지·사업성 | 홈페이지 `#studio` |
| 모형 크게 보기 ↗ | 별도의 작업 동작 | `dashboard.html?view=model&returnTo=%23studio` |

Atelier 내부 바로 가기는 **공간 모형 → 실제 `#workspaceGrid`**, **대지 조건 → `#site`**, **재료·외관 → `#materials`**, **사업성 → `#feasibility`**다. 공간 모형 바로 가기는 큰 소개 문구 대신 실제 WebGL 영역에 도착한다. 이 네 구간에서는 전역 Atelier 메뉴를 현재 위치로 표시한다.

홈페이지의 소개·Perspective·Approach·Place/Form/Value·Researcher에서는 About을 현재 구간으로 표시한다. 홈페이지 맨 위나 하단에서는 이전 메뉴 선택이 남지 않는다. 직접 주소 `#feasibility`와 `#perspective`도 같은 문서 안의 해당 구간으로 연결한다.

## 작업과 복귀

- 연구 카드: 해당 대지·모형을 선택하고 `#studio`로 이동. URL과 브라우저 뒤로 가기를 함께 갱신한다.
- 모형 크게 보기: 선택한 입력을 이어받은 모형 집중 화면. 팔레트·동영상 저장은 유지한다.
- 모형 집중의 ‘아뜰리에로’: 홈페이지 맨 위 `#home`으로 복귀한다.
- 모형 집중의 ‘상세 작업실 열기’: 같은 페이지에서 전체 작업실을 연다. Esc도 같은 동작을 유지한다.
- 사업성 상세 검토: 전체 작업실의 사업성 탭을 즉시 연다. 아뜰리에 복귀는 홈페이지 맨 위다.
- 3D 로딩 실패 시 ‘설계 조건 보기’: 전체 작업실의 설계 조건으로 직접 진입한다.
- 작업실의 FORMEQUA 로고: 홈페이지 맨 위 `#home`이다.
- 소개의 개인 홈페이지 링크: 배포된 독립 홈페이지 `https://wan2-website.web.app/`이다.

상태 저장은 기존 `workspace-state.js`를 사용한다. 새 탐색 스크립트는 계산·사용자 입력을 소유하거나 서버에 전송하지 않는다. 뒤로·앞으로 가기는 앵커 위치를 복원하고, 일반 스크롤은 브라우저 방문 기록을 늘리지 않는다. 수정된 입력을 가진 작업실에서 복귀하는 기존 동작도 유지한다.

## 파일과 책임

- `site-navigation.js/css`: 아뜰리에와 About의 공통 메뉴, 활성 구간, 앵커·방문 기록·모바일 초점.
- `editorial.js`: 연구 선택과 작업실 진입 맥락. 중복 메뉴·헤더 제어는 제거했다.
- `atelier-motion.js/css`: 문자·사진 진입 및 Approach·Inquiry의 자동 사진 장면과 분리 배치.
- `about-formequa.js/css`: 기존 About 주소 연결 및 통합 소개의 반응형 배치.
- `index.html`, `about.html`: 단일 콘텐츠·앵커와 기존 소개 주소의 호환 진입. index에 Atelier 바로 가기를 유지한다.
- `dashboard.html/css`: 집중 화면의 복귀 링크·버튼 문구·링크 스타일만 수정했다. 상단 분석표와 계산 구조는 유지한다.

2026-10-23 메뉴 정리 당시에는 계산 엔진·서버·필지·프로그램·상태 저장·모형 녹화·재료·기존 모션 파일 및 `dashboard.js` 총 13개가 변경 전 SHA-256과 일치했다. 이후 단일 스크롤 통합에서는 홈페이지 모션 파일도 위 설명대로 수정했다. 개인 홈페이지는 수정하지 않았다.

## 검증

독립 headless Edge에서 **51개 탐색 검증**을 통과했다. 세 화면의 링크 **41개**를 대조해 끊긴 내부 앵커와 중복 ID가 없음을 확인했다.

- 데스크톱의 전역 메뉴·Atelier 항목·현재 위치·고정 헤더 아래 도착.
- About ↔ 홈페이지, 모형 집중 ↔ 아뜰리에 ↔ 전체 작업실.
- 사업성 직접 진입·원래 요약 복귀·선택 필지와 변경한 금융 입력 보존.
- 브라우저 뒤로·앞으로 가기와 직접 URL 진입.
- 두 페이지의 모바일 메뉴, 첫 링크 초점, Tab·Shift+Tab 순환, Escape와 초점 복귀, 메뉴 닫힘, 화면 크기 변경.
- 390·320px 모형 집중 화면의 아뜰리에·작업실 이동 버튼.
- 일반 모션·동작 줄이기 설정에서의 위치 이동.
- 브라우저 실행 오류·누락된 로컬 리소스 없음.

기존 `workspace-state.test.js`와 `pilot-ui.test.js`도 통과했다. 테스트 중 비공개 연구 JSON 수집은 차단했다. 검증 중 발견한 메뉴 초점과 초기 앵커 문제를 수정한 뒤 해당 경로를 다시 확인했다.

결과: [navigation-verification-20261023.json](navigation-verification-20261023.json). 변경 전 파일과 테스트 스크립트·화면 캡처는 작업공간 `.backups/formequa-navigation-20261023/`에 보관한다. 서버는 기존 8090을 계속 사용하며 외부 배포는 하지 않았다.
