# FORMEQUA 공간 계획 적용 기록

검토·적용일: 2026-10-21. 이후 발견한 저장·램프·장애물·실제 필지 식별·금융 오류의 수정은 [전체 재점검](audit-20261021.md)에 기록했다. 첨부 문서의 기능군 ① HyparSpace, ② DynamoRevit·Elements, ④ TopologicPy를 적용했다. Honeybee와 물류는 제외했다.

|---|---|---|---|
| ① HyparSpace | 실별 설정, 책상 유형, 방향·그리드·통로·기둥 회피, 협업 공간 | 독립/대면/벤치/스탠딩, 0°·90° 비교, 실별 조건, 명시 장애물, 실제 좌석·협업 면적/미달 | 별도 JS 휴리스틱. Hypar 런타임·자산 없음. 임의 다각형 실·개별 좌석 접근성·최적해 미검증 |

## 사용

`dashboard.html` ‘평면·면적·외관’에서 분석 층을 선택하고 ‘배치 조건 · 동선 · BIM 전달’을 연다. 간략 매스라면 먼저 ‘상세 모형 보기’를 선택한다.

1. 업무층에서 전체 기본 또는 특정 실을 고르고 조건을 적용한다. 목표 좌석은 해당 층 전체 기준이다.
2. 호텔층에서 유형 비율·지원실 빈도·ADR 배수를 적용한다. 기본 ADR·가동률·운영비·수동 객실 수는 기존 사업성 입력으로 편집한다.
3. 확인할 위치가 있으면 고정 장애물을 해당 층 로컬 미터 좌표로 입력한다. 구조 참고 격자는 자동 장애물이 아니다.
4. ‘선택 층 동선 검토’를 실행하고 경로를 선택한다. SVG와 ‘선택 경로 3D 보기’는 같은 점을 표시한다. 내부 후보까지 연결된 것을 외부 대피 가능으로 판단하지 않는다.
5. ‘BIM 전달 JSON 저장’으로 모든 생성 층의 관계·수량·좌표를 내보낸다. 스키마 검증 실패 시 저장을 중단한다.

입력은 프로젝트 JSON·세션·분석 API에 포함하고 허용 목록·OpenAPI를 갱신했다. 금융 민감도 변경마다 동선 격자를 재계산하지 않고 선택 층에서 명시적으로 실행한다.

법정 용적률·건폐율·확인된 고시, 실제 합필/도로·지적도 좌표, 전 층 공통 코어를 유지한다. 모듈 치수·좌석 수·ADR·장애물은 계획 입력이다. 표시 수준은 금융·면적·주차 계산을 바꾸지 않는다. 경로 폭은 법정 유효폭 판정이 아니며 전달 JSON은 FORMEQUA 협업 형식이다.

## 검증 결과

JavaScript 45개 테스트 파일, Python 단위 테스트 40개, 별도 로컬 HTTP 테스트 9개를 통과했다. 새 통합 테스트는 128/129개 실별 조건 경계, 전역/실별 좌석, 유형별 호텔 매출, 장애물 캐시, 같은 경로의 SVG/3D 점, 필지/대안별 안정 ID를 확인한다. 기존 브라우저/Node 동등성 검증은 실제 HTML과 같은 의존 모듈을 로드하도록 갱신했다.

실제 8090 브라우저 검증에서 업무층 29→12석, 호텔 선택 층 표준5/트윈3/스위트2/지원2, 내부 후보 연결12/12실을 확인했다. 기준 ADR 180,000→240,000원 변경 시 전체 생성 객실 140실은 유지되고 가중 ADR은 214,200→285,600원으로 변경됐다. 15층·180실·1,020벽·320문의 BIM 전달 자료가 검증됐으며 현재 조건의 호텔 API 요청도 성공했다. 이 검증은 예시 설계의 계산·표시 연결을 확인한 것이며 호텔 허가·구조·피난 적합 판정이 아니다.

프로젝트 스킬은 `Skills-Architects/skills/formequa-space-planning/`에 보관하고 개인 스킬 폴더에도 설치했다. 공식 quick_validate와 장애물/금융/단절 신고 시나리오의 독립 forward-test를 통과했다.
