# 임대·호텔 운영 수입 모델

계산 원본은 `finance-model.js`이며 홈페이지·상세 검토·분석 API가 같은 모듈을 사용합니다. `app.js`의 개발비·PF·IRR·잔여지가 계산은 이 모듈의 수입과 NOI를 받습니다.

## 임대 모드

층별 인스펙터와 전체 계산에 동일한 수입·NOI 식을 적용합니다. 현금흐름은 아래 PF 이자·자금배분 범위를 따릅니다.

- 검토 계약면적 = 지상 연면적 + 지하 연면적 × 35%. 지하 배분분은 지상 층별 면적에 비례 배분합니다.
- 층별 월 약정 임대료(만원) = 층별 검토 계약㎡ ÷ 3.305785 × 기준 임대료(만원/계약평·월) × 대안 할증 × 외장 할증 × (0.88 + 0.12 × 용도계수).
- 층별 연수입(억원) = 월 약정 임대료 × 12 × 점유율 95% × 부가수입 계수 1.12 ÷ 10,000.
- 층별 NOI = 층별 연수입 × (1 − 운영비율 18%).

용도계수는 리테일 1.28, 업무 1.00, 주거·호텔 1.12, 공용 1.18입니다. 이 계수와 지하 35%는 기존 비교 모델의 가정이며 실제 계약·시장 자료를 의미하지 않습니다. 화면의 전용면적을 임대 계약면적으로 혼용하지 않습니다. 층별 수입·NOI의 반올림 전 합계는 전체 값과 일치합니다.

## 호텔 운영 + 비호텔 임대 모드

호텔 객실층은 `interior-plan.js`로 실제 개념 평면을 생성한 뒤 `metrics.guestRoomCount`를 합산합니다. 자동 배치 객실 수는 인허가 정원이나 주차 산정 세대수가 아닙니다. 운영 객실 수 입력을 0으로 두면 자동 배치 수를 사용하고, 양의 정수면 명시적 사용자 가정으로 사용합니다. 사용자가 가정한 수량과 자동 배치 수를 함께 표시합니다.

- 연 객실 매출 = 운영 객실 수 × 365일 × ADR × 가동률.
- 부대 매출 = 객실 매출 × 부대매출 비율.
- 총 호텔 매출 = 객실 매출 + 부대 매출.
- 변동 운영비 = 총 호텔 매출 × 운영비율.
- 위탁 수수료 = 총 호텔 매출 × 위탁 수수료율.
- FF&E 적립 = 총 호텔 매출 × FF&E 비율.
- 호텔 NOI(적립 후) = 총 호텔 매출 − 변동 운영비 − 별도 고정 운영비 − 위탁 수수료 − FF&E 적립.
- 전체 NOI = 호텔 NOI(적립 후) + 비호텔 층 임대 NOI.

ADR은 VAT·봉사료를 제외한 순 객실 단가입니다. 변동 운영비율에 별도 입력한 고정비·위탁 수수료·FF&E를 중복 포함하지 않도록 화면에 안내합니다. 호텔 객실층과 호텔 주용도의 로비·공용층에는 임대수입을 더하지 않습니다. 혼합 오피스·리테일 등 비호텔 층만 임대수입을 합산합니다.

호텔 객실층이 없는데 운영 모드를 선택하면 경고와 함께 임대 모드로 계산합니다. 실내 생성기가 없으면 자동 객실을 만들어 낸 것으로 처리하지 않고 0실과 경고를 반환합니다. 수동 객실 수가 있으면 사용자 가정으로 표시합니다.

## 사업성 반영

안정화 NOI는 기존 DSCR·매각가·사업 IRR·Equity IRR·LP/GP 현금흐름·목표수익률 잔여지가에 연결됩니다. 적자 NOI는 운영손실에 반영하고 자산 매각가는 최소 0으로 제한합니다.

기존 모델의 6개월 개업 안정화 기간에 매출·변동비·수수료·FF&E를 월별 램프업합니다. 별도 고정 운영비는 개업 첫 달부터 월액 전부를 차감합니다. 개업 전 기간의 비용은 기존 개발비 체계를 따릅니다. 안정화 후 매각하는 비교 모델이며 다년 보유 운영 모델·계절성·ADR 성장·법인세·감가상각·별도 호텔 선투입 운영자금까지 추정하지 않습니다.

### PF 및 현금흐름 포함 범위

- PF는 선·중·후순위 전체 잔액을 매각월까지 유지하는 이자 납부 방식입니다. DSCR은 안정화 NOI ÷ 전체 트랜치 연간 이자입니다. 매각월 원금 일시상환을 포함한 기간별 DSCR이나 분할상환 대출 모형은 아닙니다.
- 건설기간 금융비는 대출금 × 가중금리 × 공사연수 × 평균인출률 56% 및 대출수수료 1.5%로 개산하고 S곡선에 따라 사업비에 배분합니다. 실제 월별 인출잔액·일수·약정에 따른 건설이자 검증은 미구현입니다.
- 운영 안정화 6개월은 전체 PF 이자를 월별 자기자본 현금흐름에서 차감합니다. 건설기간 이자 예비비와 운영기 현금 이자를 중복 공제하지 않습니다.
- 무차입 Project 현금흐름은 개발비에서 PF 이자·대출수수료를 제외하고 NOI와 순매각대금을 더합니다. Equity 현금흐름은 실제 개발비 출자, 운영 NOI, 운영기 이자, 매각 시 PF 원금상환을 포함합니다.
- `equityRequiredEok`는 개발비 조달 계획입니다. `actualEquityPaidInEok`는 모든 월의 음수 Equity 현금흐름 합계로 운영적자·매각 부족분까지 포함합니다. 매각대금 부족분도 스폰서가 추가 출자한다고 가정합니다. 비소구 대출이나 유한책임 손실 제한을 구현한 결과가 아닙니다.
- LP/GP는 모든 월의 출자를 입력 지분대로 배분하고, 양수 현금흐름은 LP 원금 → GP 원금 → LP 우선수익 → 잔여 Promote 순서로 배분합니다. LP 우선수익은 직전 월말 미회수 원금에 연 허들 ÷ 12를 적용하는 단리 가정입니다. 실제 약정의 복리·catch-up·clawback·세금·차등 출자는 별도 구현 대상입니다.
- 각 월 `LP CF + GP CF = Equity CF`, 실제 LP/GP 납입 합계 = 모든 음수 Equity CF, 각자의 배당 합계 = 양수 CF로 대사합니다. IRR은 여러 부호 변화로 유일성을 확인할 수 없으면 미산정입니다.

CSV는 총지출, 금융비 제외 지출, 건설금융비 배분 개산, PF 인출, 운영기 전체 PF 이자, Project·Equity·LP·GP 현금흐름을 같은 월 기준으로 내보냅니다. 프리셋 리모델링에는 별도 임대차·견적·월별 현금흐름이 없으므로 리모델링 IRR·YoC와 대안 우위는 미산정입니다.

## 입지 입력과 검증

`hotelResidentialDistanceM`은 미확인 시 `null`이며 빈칸을 0m로 변환하지 않습니다. `hotelResidentialBarrier`도 `null`(미확인), `false`(예외 미적용), `true`(사용자 적용 근거 확인 가정)를 구분합니다. 기존 `use-permissions.js`의 거리·차단 조건에 연결하며 숫자나 차단 가정만으로 호텔 허가를 확정하지 않습니다. 실제 필지의 경계와 주거지역 경계에서 측정한 거리·관광사업계획·교육환경 검토를 확인해야 합니다.

회귀 검증: `node tests/finance-income-integration.test.js` 및 `node tests/finance-regression.test.js`.
